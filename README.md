# TeamMatch AI — 프론트엔드 프로토타입 (v3, 검토·개선본)

서버 없이 브라우저만으로 동작하는 데모입니다. 모든 데이터는 `localStorage`(계정·수업·결과)와 `sessionStorage`(로그인 세션)에만 저장되며 서버로 전송되지 않습니다.

## 실행
`index.html`을 브라우저로 열면 됩니다. (빌드 도구 불필요 · Google Fonts만 외부 요청, 막혀 있어도 기본 글꼴로 동작)

로그인은 **이메일 형식만 맞으면 어떤 주소로든** 입장합니다. 처음 쓰는 주소는 데모 계정이 자동 생성되고, 비밀번호는 검증하지 않습니다. (인증·중복·도메인 확인은 백엔드의 몫)
샘플 데이터가 들어 있는 데모 계정: 학생 `doyoon@hanyang.ac.kr` · 조교 `sumin.lee@hanyang.ac.kr` · 교수 `jiwon.han@hanyang.ac.kr`

## 구조
```
js/logic.js    DOM 비의존 순수 로직: 편성(그리디+2-교환 지역 탐색), 점수, 제약 검증, 팀 수 계획, 요구사항 키워드 해석
js/store.js    상태 모델(계정 레지스트리·수업별 setup/roster/result/tas), 시드, 저장/복원, 셀렉터
js/ui.js       접근성 있는 공통 컴포넌트(switch·radiogroup·<dialog>·폼 오류·CSV·히트맵)
js/auth.js     로그인/가입(필드별 검증)   js/router.js  해시 라우팅·가드·사이드바
js/pages/...   화면(학생 5 · 교수 7(프로필 포함), 조교는 교수 화면을 읽기 전용으로 재사용)
```

## 원본(업로드본) 대비 고친 것
| 구분 | 원본의 문제 (브라우저에서 재현 확인) | 수정 |
|---|---|---|
| 데이터 모델 | 설정·결과·조교가 **전역 1개**라 수업을 바꿔도 같은 결과가 다른 수업 제목 아래 표시됨 | 수업마다 `setup/roster/result/tas` 분리 |
| 수치 일관성 | 대시보드 38/45, 제출 현황 33/44, 머신러닝개론 12/41 vs 31/41 | 모든 수치를 roster에서 계산 |
| 미리보기 ≠ 결과 | "9팀"이라 안내하고 실제 11팀 생성, "인원 나누어지지 않을 때" 옵션은 미연결 | `planTeamCount()` 한 함수를 미리보기와 알고리즘이 공유, 옵션 연결 |
| 재실행 | 같은 입력이면 항상 동일 결과 | 시드 + 5회 재시작, 고정한 팀은 재실행해도 유지 |
| 가짜 값 | "실행 09.21 10:05", "미제출자 7명", "공통 가능 주 N시간(평균/2.4)" | 실행 시각·미제출 수 실계산, 공통 시간은 실제 교집합 |
| 가중치 | "1 = 고려하지 않음"인데 1점도 계산에 포함 | 1점은 0%로 처리, 실제 반영 비율(%) 표시 |
| 요구사항 | 해석 결과가 고정된 3줄, 체크해도 편성에 무영향 | 키워드 해석 → 알고리즘 반영 → 결과에서 검증 |
| 저장 | 프리셋 저장 토스트는 뜨지만 새로고침하면 사라짐 | 모든 변경 `save()`, pagehide 시 flush |
| 계정 데이터 | 가입해도 김도윤 프로필을 물려받고, 학년이 몰래 "3학년"으로 채워짐 | 계정별 빈 프로필, 학년은 필수 입력 |
| 흐름 단절 | 참여 코드를 입력할 학생 UI 없음, 확정해도 학생에게 반영 안 됨, 조교 권한이 아무 효과 없음 | 코드 참여, 확정→학생 프로젝트 생성, 조교 메뉴(열람·리마인드) |
| 범위 이탈 | 프로젝트에 '진행률' (기획안 1-3에서 제외한 진행 관리) | '첫 모임 준비 n/4'만 표시 |
| UX | `prompt()` 3연타 교환, `confirm()`, 84칸 개별 클릭, 뒤로가기 시 앱 이탈 | 클릭 교환, `<dialog>`, 칠하기·드래그, 해시 라우팅 |
| 접근성 | `<label>`을 스위치로 사용, 시간표 칸 이름 없음, 포커스 이동 없음, 닫힌 모바일 메뉴도 Tab 이동됨 | role=switch/radiogroup, aria-label, `inert`, 포커스·Esc, aria-live |

## 알려진 한계 (프론트엔드만으로는 해결 불가)
- 비밀번호·이메일 인증·권한은 **실제 보안이 아님**(브라우저에서 누구나 DevTools로 변경 가능). 중복 가입·도메인 검증 같은 서버 검증은 일부러 넣지 않았음.
- 교수 계정이 여러 개여도 수업·프리셋은 공유됨(수업에 소유자 개념 없음). 그래서 교수가 탈퇴해도 수업 데이터는 남는다 — 서비스에서는 수업 소유·이관 정책이 필요.
- 이메일·비밀번호 변경은 프로필에서 지원하지 않음(로그인 서버 연동 후).
- "AI 해석"은 키워드 규칙이며 LLM이 아님. 자기소개·외부 링크 분석(기획안 3-1 나항)은 구현하지 않았음.
- 데이터는 한 브라우저 안에서만 공유됨(학생·교수가 동시에 다른 기기에서 쓰는 협업은 서버 필요).
- 알림(리마인드)은 횟수만 기록하며 실제 발송하지 않음. 편입·유학생 정보는 학적 연동이 필요해 모의 학생에게만 존재.
- 기획안 대비 미구현: 외부 링크 입력/동의, 설문 문항 편집·템플릿 전환, 첫 모임 아젠다의 협업 유의사항 자동 문구.

## 백엔드 연결 지점
프론트엔드는 "화면과 UX"만 맡고, 아래 항목은 서버가 생기면 교체/이관합니다.

| 위치 | 지금(데모) | 서버가 생기면 |
|---|---|---|
| `js/auth.js` → `AuthApi.login / signup / withdraw` | 이메일 형식만 보고 계정 자동 생성, 탈퇴 시 데이터 삭제·익명화(`store.js`의 `purgeAccount`) | `POST /auth/login`, `/auth/signup`, `DELETE /account`. 인증·중복·이메일 소유·도메인 검증과 탈퇴 후 데이터 보존·이관 정책은 서버. 반환 형태(`{ok, email, …}`)는 유지 |
| `js/store.js` → `initStore / save` | `localStorage`에 전체 상태 저장 | 엔티티별 API 호출 (`accounts`, `classes[roster·setup·result·tas]`, `presets`, `projects`) |
| `js/store.js` 하단 `joinClass / publishProjects / withdrawProjects` | 브라우저에서 직접 연결·생성 | 서버 도메인 로직(참여 코드 확인, 확정 시 프로젝트 생성) |
| `js/logic.js` → `TM.solve` | 브라우저에서 편성 계산 | 서버로 이관해도 입력(참가자·설정)/출력(teams) 계약과 `tests/logic.test.js`를 그대로 재사용 가능. `TM.evaluate`는 교환 시 즉시 재계산용으로 프론트에 남겨도 됨 |

프론트에 계속 남는 것: 입력 형식 검증(UX), 로그인 여부·역할에 따른 화면 분기와 라우트 가드(UX용이며 보안 경계는 서버).
